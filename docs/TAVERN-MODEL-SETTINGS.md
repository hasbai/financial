## 设置、默认值与模型边界

| 设置 | 应用默认值 | 校验 / 请求行为 |
| --- | --- | --- |
| 模型 `modelId` | `rp`，显示“RP 动态路由” | 服务端白名单映射到 `dynamic/rp`，首期只提供这一个真实选项 |
| 启用思考 `thinkingEnabled` | **false，关闭** | 必须是布尔值；通过真实上游支持的参数关闭，不靠隐藏输出或提示词实现 |
| 温度 `temperature` | 0.9 | 0–2，步长 0.05；上游范围更窄时按能力限制 |
| Top P `topP` | 1 | 大于 0 且不超过 1，步长 0.01；实际传 `top_p` |
| Top K `topK` | 0，显示“模型默认” | 0 表示不覆盖上游设置，请求省略字段；非零为正整数，范围取真实路由能力 |
| 频率惩罚 `frequencyPenalty` | 0 | 目标范围 −2–2，实际传 `frequency_penalty`，仅在路由支持时开放 |
| 存在惩罚 `presencePenalty` | 0 | 目标范围 −2–2，实际传 `presence_penalty`，仅在路由支持时开放 |
| 回复长度上限 `maxTokens` | 4096 | 保留现有 128–8192 和上下文预算校验，实际传 `max_tokens` |

这些是应用默认配置，不代表全部上游都支持。Top K 为 0 不等于关闭上游 Top K；Top P 为 1 保持宽松默认，温度继续承担主要采样调节。不先添加未经要求、未经真实验证的 Min P、种子或额外采样器。

服务端模型注册表统一保存逻辑 ID、显示名、实际路由和已验证的参数能力。计划增加 `GET /api/models`，只返回可选择项、公共能力、默认值和边界；不返回 BYOK alias、密钥、内部 URL 或完整路由配置。浏览器仅提交 `modelId`，未知 ID 返回字段错误；生成请求不能携带任意模型或路由覆盖。首期只有 RP，不造其他可选模型。路由所有可达模型分支必须遵守同一已验证的能力契约，后续改变网关模型时重验。

优先核实 RP 的真实 provider/model 和关闭思考字段。不同上游可能使用不同的 reasoning/thinking 字段，不能把某一供应商格式直接认作 RP 的格式。不能在报错后悄悄去掉关闭思考参数重试。若当前路由不能保证关闭，必须在实施阶段解决路由支持并完成验证，不能将本功能标记为已交付。不支持的可选采样控件显示禁用状态和“不可用”徽标，禁止显示可编辑却实际忽略的参数。

共享默认值、归一化、校验和模型请求映射供设置读写、会话读写、创建、分支及实际生成共用；不只在设置页补默认值。历史用户设置与会话缺少新增字段时补默认，保留已有名称、persona、系统提示、temperature、maxTokens、记录和 ID。特别是缺少思考字段一律得到 false。

全局设置作为新会话默认；现有会话使用自己的快照，通过会话设置保存。两处复用同一生成参数组件，会话参数不能隐藏在全局之后。界面用“新会话默认”与“当前会话”区分范围，不增加说明段落。提供“恢复默认”操作，只重置模型和生成参数草稿，不清除身份设定；保存后才生效。生成期间禁止修改当前会话参数；请求启动时使用一致的配置快照。

## 设置页视觉与交互

沿用北极小站雪花标识、Luma neutral 色板、Lucide 与已有深浅主题，保持页面约 760px 的阅读宽度。

1. 顶部为“对话设置”和主题按钮；正文依次分为“模型”“生成参数”“角色设定”三组，模型选择与思考开关放第一屏。思考使用清晰的 Switch，初始关闭，不使用需要理解反向含义的“禁用思考”。
2. 生成参数桌面双列、手机单列。温度与 Top P 使用滑杆加可直接输入的数值框；Top K 与惩罚项使用紧凑数值控件。标签保留 Top P / Top K，长标签和错误自然换行。参数边界、错误就近显示。
3. 姓名、persona 与系统提示放角色设定组，不让大段 textarea 挤掉模型配置。保留正常可编辑功能，分组依靠标题、间距、细边框表达。
4. 页底“恢复默认”“保存设置”，保存中禁用重复提交，成功显示短状态。会话设置复用参数组；移动端弹层内容可滚动，底部操作不遮住字段和软键盘。
5. 不增加技术横幅、参数教学、tooltip 搬运说明或虚构推荐值。所有字段有标签，键盘焦点可见，触摸目标至少 44px，状态不只靠颜色区分。

## 续聊候选内容与 UI

每次 roleplay 的一次模型调用先输出正文，再顺带输出最多三条候选。候选只有在该回复正常完成、协议与内容校验通过后可点击；停止、失败、预算耗尽和不可靠终态均丢弃候选。成功续写或重新生成也使用同一协议。现有开场白和旧历史不补发模型请求。

候选必须是**用户视角的完整可发送文本**，承接最新故事、用户 persona 和角色设定，语义有区分、不替用户预设选择、不虚构已发生事件。不生成角色自己的回复，不返回抽象标签如“继续探索”。依据上下文区分方向，不固定每轮相同模板。每条建议 15–60 个字符，服务端硬上限 120 个 Unicode 字符；候选可以是用户行动或台词。生成示例只放测试夹具，不作为生产兜底。

只在最新回复下方显示“接下来”和候选按钮，处于消息阅读列内，不给全部历史挂按钮，不占固定输入区。桌面最多三张轻边框按钮，内容较长时自然换行；手机纵向排列。整条候选可点击，右侧小箭头表示发送，文本完整可读。正文输出到尾部时在同一位置显示短骨架，不抢焦点、不强制滚动、不覆盖消息或输入框。候选无效时省略按钮，不弹全屏错误；没有合格文本时不拿固定候选补足三条。

点击候选直接发送其完整原文，不先填输入框再要求确认。重构现有发送入口为显式 content/source 入参，候选发送与手动输入复用相同 UUID、正文锁和异常处理。候选发送保留正在编辑的自由输入草稿；手动发送仍按现有规则清空已提交文本，启动失败时恢复。候选发送前再次验证关联最新回复，同步进入发送状态，防双击和键盘重复触发。

正文与候选共用现有生成锁；尾部期间允许编辑自由输入草稿，发送等待本轮完成。正常完成立即解锁，禁止额外候选等待。发送下一轮、重新生成、切会话、编辑分支或删除后，旧候选退出当前界面，迟到结果不能插入新会话。失败不会清空草稿。保留 Enter 发送、Shift+Enter 换行和中文 IME 保护。

## 一次预填充、流式正文与候选尾部

沿用 `POST /api/sessions/:id/generate` 与现有 UUID/原子锁，只调用一次 `dynamic/rp`。Prompt 在同一次请求中要求正文后追加请求专属分隔符及候选 JSON。不新增候选推理接口、额外 lease 或点击“重试候选”的第二次调用。任务 metadata 始终为 `{ app: "tavern", task: "roleplay", username: verifiedJwtUsername }`，生成、重新生成、续写同样遵守。

正文继续按纯文本增量流式输出。服务端解析状态机为 `body → delimiter → candidates → validate → done`，保留可能跨 chunk 的分隔符前缀，避免把协议字符或 JSON 提前传到正文。分隔符包含请求 nonce，避免把普通故事内容误认成协议；候选尾部大小限制 2KB。模型请求整体受既有超时/停止/正文长度上限保护，不自动重试。

正常 `stop` 后接受 1–3 条非空字符串，去首尾空格、去重，每条最多 120 个 Unicode 字符；超三条取前三条合格文本，全部无效或 JSON 不完整则不显示候选。尾部缺失时保留正常正文，记录协议未生成状态，不补一次推理。`length`/取消/断网/异常结束保存已输出正文与原有终止原因，丢弃候选，不把协议文本或不完整 JSON写入正文。

候选与所属 message ID 一起在终态保存，为 `messages` 增加 nullable JSON 元数据列，旧记录保持 NULL，保留正文与 ID。刷新只读已存结果；重新生成、续写为新 message ID，分支不复制旧候选。候选不是额外消息，也不进入下一轮 Prompt。SSE 通过独立的候选事件或 done 消息元数据通知前端；只有当前会话最新正常版本且已解锁才可发送。重复原 UUID仍返回既有生成结果，不再推理，所有状态复用现有请求幂等机制。

所有推理通过 AI Gateway；开启请求日志及三个归属字段，`skipCache:true`，通过 `cf-aig-collect-log-payload:false` 独立关闭正文存储，不使用 `collectLog:false`。用户名只取已验签的 Auth0 JWT 专属 claim；前端只传 Access Token，后端不逐轮查询 Auth0 Management API 或 `/userinfo`，不采用 RP persona 名称、用户 ID 或客户端 metadata。缺名称的旧 Token在占锁和模型请求前返回明确重新登录错误。Action 必须先发布，让新 Token带名称，再发布依赖该 claim 的 Worker。

## 上游反馈驱动的短上下文预算

已移除 `CONTEXT_TOKENS=16000` 固定预算。运行时以 Gateway 路由版本、官方模型 schema 和 Workers AI `context_window` 读取能力，D1 缓存5分钟，刷新以 CAS 防止迟到旧版本覆盖；路由变更为未验证的模型/拓扑时明确拒绝生成，不猜参数。现有模型官方反馈为256000；16K/32K为自动化短窗口用例。凭据仅作服务端 Secret，用于能力读取，身份流程依旧直接验签 JWT。16K 和 32K 是需支持的短窗口案例，不是全局写死的模型能力。

可信上限来自上游/路由模型配置、能力端点明确给出的 `context_length` / `max_model_len`，或可归因于实际模型的明确 token-limit 错误。服务端按路由版本和实际模型保存已验证能力/来源/有效期，路由切换或模型能力变化后失效；多可达模型使用共同安全上限。若只有某一次响应的模型标识，不能假定路由以后总是该模型。

`usage.prompt_tokens` 是本轮使用量，不是窗口上限；成功请求只给可用下界。不能从“本轮没出错”或低 token 用量宣称自动发现 32K。未知能力标为 unknown：使用仍有效的已验证安全预算；没有安全预算时先完成只读能力核实，不能为一次对话猜大窗口或通过大量付费请求撞边界。

规划计算为：可用输入 = 已证实上下文上限 − 本轮总输出预算 − tokenizer/协议安全余量。总输出预算包含正文和候选尾部，不另外追加到用户的输出上限之外；4096预算可分配正文目标约3712与候选目标约384，数字为规划分配、不是模型硬保证。若上游要求思考，思考用量也消耗输出容量；默认关闭思考须经真实验证。

优先使用上游支持的 tokenizer/计数能力；无法获得时保留现有字符估算与明确安全余量，并按实际 usage 校准估算偏差。优先保留系统、角色、persona、必要世界书、最新完整轮次和当前输入；按相关性/预算筛选世界书，裁剪较早完整轮次，不额外调用模型做摘要。核心设定与最新输入仍超预算时生成前明确错误，不悄悄丢当前输入。

上游明确反馈更小上限时校正该模型能力缓存，本轮按原有失败状态保存，允许用户显式重试；不自动重新预填充或重复付费请求。源反馈含糊或无法归因模型时不改能力上限。HTML 预算图中的16K/32K是方案演示，未知模式不显示伪造的已探知容量。

## 官方契约依据与待核实项

- [Cloudflare 动态路由调用](https://developers.cloudflare.com/ai-gateway/features/dynamic-routing/usage/)：使用固定逻辑路由，实际模型由网关决定；应用选择项不能等价于任意上游模型输入。

实施时读取真实 RP 路由配置和供应商官方契约并验证透传、参数范围、关闭/开启思考、结构化输出及候选延迟；这些证据尚缺，不影响本轮完成方案，但不能宣称功能已上线。
