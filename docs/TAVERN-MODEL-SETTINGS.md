## 当前实现与目标差异

已实现参数默认值、全局/会话设置、默认关闭思考、同次候选、持久化及点击发送。RP 当前指向本地 llama.cpp 的 Qwen 模型；实际 provider/model 交给 Gateway。参数直接透传，不以路由版本、schema 或管理 API 核验作为聊天准入条件。运行时不依赖管理 Token 或推理 API Key。
现有正常完成、停止、续写、重新生成、分支和预算校验保留。本地上游模型较慢，新增候选必须与正文共用一次 roleplay 生成和预填充；不安排第二次候选推理。尾部解析失败不能把正常正文改成失败。

## 设置、默认值与模型边界

| 设置 | 应用默认值 | 校验 / 请求行为 |
| --- | --- | --- |
| 模型 `modelId` | `rp`，显示“RP 动态路由” | 服务端白名单映射到 `dynamic/rp`，首期只提供这一个真实选项 |
| 启用思考 `thinkingEnabled` | **false，关闭** | 必须是布尔值；通过真实上游支持的参数关闭，不靠隐藏输出或提示词实现 |
| 温度 `temperature` | 0.9 | 0–2，步长 0.05 |
| Top P `topP` | 1 | 大于 0 且不超过 1，步长 0.01；实际传 `top_p` |
| Top K `topK` | 0，显示“模型默认” | 0 表示不覆盖上游设置，请求省略字段；非零为 1–1000 的整数，直接传 top_k |
| 频率惩罚 `frequencyPenalty` | 0 | 目标范围 −2–2，实际传 `frequency_penalty`，直接透传 |
| 存在惩罚 `presencePenalty` | 0 | 目标范围 −2–2，实际传 `presence_penalty`，直接透传 |
| 回复长度上限 `maxTokens` | 4096 | 保留现有 128–8192 和上下文预算校验，实际传 `max_tokens` |

这些是应用默认配置，不代表全部上游都支持。Top K 为 0 不等于关闭上游 Top K；Top P 为 1 保持宽松默认，温度继续承担主要采样调节。不先添加未经要求、未经真实验证的 Min P、种子或额外采样器。

`GET /api/models` 返回 RP 选项及已获取的上下文容量。RP 始终可选，客户端仅提交逻辑 ID，不接受任意上游模型、路由、URL 或密钥。未知 ID 返回字段错误。

标准参数随请求直接发送，默认 `chat_template_kwargs.enable_thinking:false`，同时 `reasoning_effort:none`；开启时改为 true/low。`reasoning_format:deepseek` 分离思考与正文，不用隐藏输出代替关闭思考。上游报错按现有失败状态保存，不删参数重试，不添加备用模型。
共享默认值、归一化、校验和模型请求映射供设置读写、会话读写、创建、分支及实际生成共用；不只在设置页补默认值。历史用户设置与会话缺少新增字段时补默认，保留已有名称、persona、系统提示、temperature、maxTokens、记录和 ID。特别是缺少思考字段一律得到 false。

全局设置作为新会话默认；现有会话使用自己的快照，通过会话设置保存。两处复用同一生成参数组件，会话参数不能隐藏在全局之后。界面用“新会话默认”与“当前会话”区分范围，不增加说明段落。提供“恢复默认”操作，只重置模型和生成参数草稿，不清除身份设定；保存后才生效。生成期间禁止修改当前会话参数；请求启动时使用一致的配置快照。

## 设置页视觉与交互

沿用北极小站雪花标识、Luma neutral 色板、Lucide 与已有深浅主题，保持页面约 760px 的阅读宽度。

1. 顶部为“对话设置”和主题按钮；正文依次分为“模型”“生成参数”“角色设定”三组，模型选择与思考开关放第一屏。思考使用清晰的 Switch，初始关闭，不使用需要理解反向含义的“禁用思考”。
2. 生成参数桌面双列、手机单列。温度与 Top P 使用滑杆加可直接输入的数值框；Top K 与惩罚项使用紧凑数值控件。标签保留 Top P / Top K，长标签和错误自然换行。参数边界、错误就近显示。
3. 姓名、persona 与系统提示放角色设定组，不让大段 textarea 挤掉模型配置。保留正常可编辑功能，分组依靠标题、间距、细边框表达。
4. 页底“恢复默认”“保存设置”，保存中禁用重复提交，成功显示短状态。会话设置复用参数组；移动端弹层内容可滚动，底部操作不遮住字段和软键盘。
5. 不增加技术横幅、参数教学、tooltip 搬运说明或虚构推荐值。所有字段有标签，键盘焦点可见，触摸目标至少 44px，状态不只靠颜色区分。

## 续聊候选内容与 UI

每次 roleplay 的一次模型调用先输出正文，再顺带输出最多三条候选。候选只有在该回复正常完成、协议与内容校验通过后可点击；停止、失败、预算耗尽和不可靠终态均丢弃候选。成功续写或重新生成也使用同一协议。现有开场白和旧历史不补发模型请求。

候选必须是**用户视角的完整可发送文本**，承接最新故事、用户 persona 和角色设定，语义有区分、不替用户预设选择、不虚构已发生事件。不生成角色自己的回复，不返回抽象标签如“继续探索”。依据上下文区分方向，不固定每轮相同模板。每条建议 15–60 个字符，服务端硬上限 120 个 Unicode 字符；候选可以是用户行动或台词。生成示例只放测试夹具，不作为生产兜底。

只在最新回复下方显示“接下来”和候选按钮，处于消息阅读列内，不给全部历史挂按钮，不占固定输入区。桌面最多三张轻边框按钮，内容较长时自然换行；手机纵向排列。整条候选可点击，右侧小箭头表示发送，文本完整可读。正文输出到尾部时在同一位置显示短骨架，不抢焦点、不强制滚动、不覆盖消息或输入框。候选无效时省略按钮，不弹全屏错误；没有合格文本时不拿固定候选补足三条。

点击候选直接发送其完整原文，不先填输入框再要求确认。重构现有发送入口为显式 content/source 入参，候选发送与手动输入复用相同 UUID、正文锁和异常处理。候选发送保留正在编辑的自由输入草稿；手动发送仍按现有规则清空已提交文本，启动失败时恢复。候选发送前再次验证关联最新回复，同步进入发送状态，防双击和键盘重复触发。

正文与候选共用现有生成锁；尾部期间允许编辑自由输入草稿，发送等待本轮完成。正常完成立即解锁，禁止额外候选等待。发送下一轮、重新生成、切会话、编辑分支或删除后，旧候选退出当前界面，迟到结果不能插入新会话。失败不会清空草稿。保留 Enter 发送、Shift+Enter 换行和中文 IME 保护。

## 一次预填充、流式正文与候选尾部

沿用 `POST /api/sessions/:id/generate` 与现有 UUID/原子锁，只调用一次 `dynamic/rp`。Prompt 在同一次请求中要求正文后追加固定独占一行的 `[TAVERN_NEXT]` 分隔符及最多三行候选文本。不新增候选推理接口、额外 lease 或点击“重试候选”的第二次调用。任务 metadata 始终为 `{ app: "tavern", task: "roleplay", username: verifiedJwtUsername }`，生成、重新生成、续写同样遵守。

正文继续按纯文本增量流式输出。服务端解析状态机为 `body → delimiter → candidates → validate → done`，保留可能跨 chunk 的分隔符前缀，避免把协议字符提前传到正文。分隔符不含请求 UUID，系统提示保持稳定；该独占行是保留协议标记，不用于正文；候选尾部大小限制 2KB。模型请求整体受既有超时/停止/正文长度上限保护，不自动重试。

本轮最后一条 user 请求副本末尾附加固定的应用格式提醒，正常生成、重新生成、续写共用；提醒先计入输入预算，只追加一次，不改变持久化、显示或导出的用户原文，也不追加到旧历史。它与稳定 System 协议共同要求正文后输出候选，不另开推理请求。

正常 `stop` 后接受 1–3 条非空字符串，去首尾空格、去重，每条最多 120 个 Unicode 字符；超三条取前三条合格文本，全部无效、结构化包装或超长尾部则不显示候选。尾部缺失时保留正常正文，记录协议未生成状态，不补一次推理。`length`/取消/断网/异常结束保存已输出正文与原有终止原因，丢弃候选，不把协议文本写入正文。

候选与所属 message ID 一起在终态保存，为 `messages` 增加 nullable JSON 元数据列，旧记录保持 NULL，保留正文与 ID。刷新只读已存结果；重新生成、续写为新 message ID，分支不复制旧候选。候选不是额外消息，也不进入下一轮 Prompt。SSE 通过独立的候选事件或 done 消息元数据通知前端；只有当前会话最新正常版本且已解锁才可发送。重复原 UUID仍返回既有生成结果，不再推理，所有状态复用现有请求幂等机制。

所有推理通过 AI Gateway；开启请求日志及三个归属字段，`skipCache:true`，通过 `cf-aig-collect-log-payload:true` 保存完整请求与回复，不使用 `collectLog:false`。用户名只取已验签的 北极小站共享 Auth0 JWT 公共 claim；前端只传 Access Token，后端不逐轮查询 Auth0 Management API 或 `/userinfo`，不采用 RP persona 名称、用户 ID 或客户端 metadata。缺名称的旧 Token在占锁和模型请求前返回明确重新登录错误。Action 必须先发布，让新 Token带名称，再发布依赖该 claim 的 Worker。

## 上游反馈驱动的短上下文预算

已移除固定16000预算。本地服务只读 `/props` 给出实际运行 `n_ctx`（2026-10-03核实为32768），不是训练窗口。D1保存一个容量缓存，过期后后台刷新；探测短超时、有限响应，不在生成前等待，不需要管理凭据。16K/32K按实际容量裁剪。

未知容量或探测失败仍允许聊天：保留全部有效历史（包括最初问候和最早用户消息）与已激活世界书，不在未知容量下主动截断，不猜窗口，不额外生成摘要。未知模式不能保证一定不超限；只有获得明确上限后才按预算裁剪。usage只表示本轮用量，不用作窗口上限。
规划计算为：可用输入 = 已证实上下文上限 − 本轮总输出预算 − tokenizer/协议安全余量。总输出预算包含正文和候选尾部，不另外追加到用户的输出上限之外；4096预算可分配正文目标约3712与候选目标约384，数字为规划分配、不是模型硬保证。若上游要求思考，思考用量也消耗输出容量；默认关闭思考须经真实验证。

优先使用上游支持的 tokenizer/计数能力；无法获得时保留现有字符估算与明确安全余量。优先保留系统、角色、persona、必要世界书、最新完整轮次和当前输入；按相关性/预算筛选世界书，裁剪较早完整轮次，不额外调用模型做摘要。核心设定与最新输入仍超预算时生成前明确错误，不悄悄丢当前输入。

上游明确反馈更小上限时校正容量缓存，本轮按原有失败状态保存，允许用户显式重试；不自动重新预填充或重复付费请求。源反馈未明确上下文上限时不改缓存。HTML 预算图中的16K/32K是方案演示，未知模式不显示伪造的已探知容量。

## 实施顺序与验收

| 顺序 | 工作 | 必过条件 |
| --- | --- | --- |
| 1 | 统一默认值/校验/参数透传、固定 RP | 默认发送思考 false；路由调整不阻断对话；缺省旧会话仍可读写 |

| 3 | 候选 D1 兼容迁移、尾部解析和原请求幂等 | 隔离 D1 先验证；一次调用完成正文与候选；跨 chunk 解析、截断丢弃、原 UUID去重；不污染历史 |
| 4 | 候选按钮、显式发送入口、状态隔离 | 最多三条、原文点击发送、草稿保留、尾部可编辑草稿；切会话/分支/重生成丢弃旧结果 |

浏览器与视觉清单覆盖设置和会话设置正常/加载/错误/保存/恢复默认、候选等待/成功/失败/空结果/发送、长句、iPhone WebKit、desktop、深色、键盘与减弱动效。输入可用、无横向溢出、软键盘/安全区不遮挡操作分别检查；设备模拟不算真机。

## 对话 UI 与提示词修订（2026-10-03）

消息区采用右侧用户气泡、无气泡角色正文，当前单角色会话隐藏双方姓名与头像，保留无障碍身份。发送/停止使用44px圆形图标按钮；输入框单行起步，按实际内容伸展到200px后内部滚动，发送后复位。复制、编辑与最后一条回答的重新生成放正文末尾；保留键盘、中文输入法、停止、续写和草稿。

全局与当前会话都可编辑 System Prompt，并独立恢复默认提示；全局用于新会话，现有会话保留自身快照。默认鼓励3–6段、约300–600字的自然对白与场景细节，仍由用户控制自己的行动；长度是提示目标，实际受模型及输出上限约束。只精确升级旧默认字符串，用户自定义内容不覆盖；用户提示始终进入system，角色卡提示附加，含 `{{original}}` 时替换且不重复插入。固定候选标记不含UUID，有利于稳定前缀，不承诺缓存一定命中。

Gateway 当前通过 universal 绑定调用动态路由；原始流继续实时传送，Gateway日志同时聚合 `choices[0].delta.content` 并保留 `streamed_data`。不在应用端回写 response 或借 metadata 存正文，不增第二次推理，也不改为非流式。旧 `/run` 记录不能追溯改写成聚合格式。
