# Tavern 模型设置与续聊候选

2026-10-03。状态：规划完成，功能待实施。入口为 `apps/tavern`，从 [总方案](TAVERN.md) 和 [交付状态](TAVERN-PROGRESS.md) 进入。本次目标是减少回复等待，完整提供参数设置，并在每轮正常回复后提供最多三条可直接发送的后续输入。

## 当前实现与目标差异

当前 `shared/types.ts` 的默认值为 temperature 0.9、maxTokens 4096；用户设置和会话快照分别保存在 D1 JSON 中。`worker/generation.ts` 固定调用 `AI.run('dynamic/rp', ...)`，只传温度和输出上限。流式解析过滤思考内容，但没有向上游发送关闭思考参数。`Settings.svelte` 只有 persona、系统提示、温度和长度；`Chat.svelte` 没有续聊候选。

现有正常完成、停止、续写、重新生成、分支和预算校验保留。新增候选独立于正文生成，候选服务故障不能把正常回复改成失败。

## 设置、默认值与模型边界

| 设置 | 应用默认值 | 校验 / 请求行为 |
| --- | --- | --- |
| 模型 `modelId` | `rp`，显示“RP 动态路由” | 服务端白名单映射到 `dynamic/rp`，首期只提供这一个真实选项 |
| 启用思考 `thinkingEnabled` | **false，关闭** | 必须是布尔值；通过真实上游支持的参数关闭，不靠隐藏输出或提示词实现 |
| 温度 `temperature` | 0.9 | 0–2，步长 0.05；上游范围更窄时按能力限制 |
| Top P `topP` | 1 | 大于 0 且不超过 1，步长 0.01；实际传 `top_p` |
| Top K `topK` | 0，显示“模型默认” | 0 表示不覆盖上游设置，请求省略字段；非零为正整数，范围取真实路由能力 |
| 频率惩罚 `frequencyPenalty` | 0 | 目标范围 −2–2，实际传 `frequency_penalty`，仅在路由支持时开放 |
| 存在惩罚 `presencePenalty` | 0 | 目标范围 −2–2，实际传 `presence_penalty`，仅在路由支持时开放 |
| 回复长度上限 `maxTokens` | 4096 | 保留现有 128–8192 和上下文预算校验，实际传 `max_tokens` |

这些是应用默认配置，不代表全部上游都支持。Top K 为 0 不等于关闭上游 Top K；Top P 为 1 保持宽松默认，温度继续承担主要采样调节。不先添加未经要求、未经真实验证的 Min P、种子或额外采样器。

服务端模型注册表统一保存逻辑 ID、显示名、实际路由和已验证的参数能力。计划增加 `GET /api/models`，只返回可选择项、公共能力、默认值和边界；不返回 BYOK alias、密钥、内部 URL 或完整路由配置。浏览器仅提交 `modelId`，未知 ID 返回字段错误；生成请求不能携带任意模型或路由覆盖。首期只有 RP，不造其他可选模型。路由所有可达模型分支必须遵守同一已验证的能力契约，后续改变网关模型时重验。

优先核实 RP 的真实 provider/model 和关闭思考字段。不同上游可能使用不同的 reasoning/thinking 字段，不能把某一供应商格式直接认作 RP 的格式。不能在报错后悄悄去掉关闭思考参数重试。若当前路由不能保证关闭，必须在实施阶段解决路由支持并完成验证，不能将本功能标记为已交付。不支持的可选采样控件显示禁用状态和“不可用”徽标，禁止显示可编辑却实际忽略的参数。

共享默认值、归一化、校验和模型请求映射供设置读写、会话读写、创建、分支及实际生成共用；不只在设置页补默认值。历史用户设置与会话缺少新增字段时补默认，保留已有名称、persona、系统提示、temperature、maxTokens、记录和 ID。特别是缺少思考字段一律得到 false。

全局设置作为新会话默认；现有会话使用自己的快照，通过会话设置保存。两处复用同一生成参数组件，会话参数不能隐藏在全局之后。界面用“新会话默认”与“当前会话”区分范围，不增加说明段落。提供“恢复默认”操作，只重置模型和生成参数草稿，不清除身份设定；保存后才生效。生成期间禁止修改当前会话参数；请求启动时使用一致的配置快照。

## 设置页视觉与交互

沿用北极小站雪花标识、Luma neutral 色板、Lucide 与已有深浅主题，保持页面约 760px 的阅读宽度。

1. 顶部为“对话设置”和主题按钮；正文依次分为“模型”“生成参数”“角色设定”三组，模型选择与思考开关放第一屏。思考使用清晰的 Switch，初始关闭，不使用需要理解反向含义的“禁用思考”。
2. 生成参数桌面双列、手机单列。温度与 Top P 使用滑杆加可直接输入的数值框；Top K 与惩罚项使用紧凑数值控件。标签保留 Top P / Top K，长标签和错误自然换行。参数边界、错误就近显示。
3. 姓名、persona 与系统提示放角色设定组，不让大段 textarea 挤掉模型配置。保留正常可编辑功能，分组依靠标题、间距、细边框表达。
4. 页底“恢复默认”“保存设置”，保存中禁用重复提交，成功显示短状态。会话设置复用参数组；移动端弹层内容可滚动，底部操作不遮住字段和软键盘。
5. 不增加技术横幅、参数教学、tooltip 搬运说明或虚构推荐值。所有字段有标签，键盘焦点可见，触摸目标至少 44px，状态不只靠颜色区分。

## 续聊候选内容与 UI

每次**正常完成**的助手回复自动触发独立模型调用，目标三条，上限三条；停止、失败、预算耗尽和无可靠终态不触发。成功续写或重新生成产生的新回复版本同样触发。现有开场白和旧历史没有可靠的 `stop` 证据，不批量补生成；从本功能上线后的正常完成回复开始。

候选必须是**用户视角的完整可发送文本**，承接最新故事、用户 persona 和角色设定，语义有区分、不替用户预设选择、不虚构已发生事件。不生成角色自己的回复，不返回抽象标签如“继续探索”。依据上下文区分方向，不固定每轮相同模板。每条建议 15–60 个字符，服务端硬上限 120 个 Unicode 字符；候选可以是用户行动或台词。生成示例只放测试夹具，不作为生产兜底。

只在最新回复下方显示“接下来”和候选按钮，处于消息阅读列内，不给全部历史挂按钮，不占固定输入区。桌面最多三张轻边框按钮，内容较长时自然换行；手机纵向排列。整条候选可点击，右侧小箭头表示发送，文本完整可读。等待时在同一位置显示短骨架，不抢焦点、不强制滚动、不覆盖消息或输入框。失败显示紧凑“重试”入口，不弹全屏错误；没有合格文本时不拿固定候选补足三条。

点击候选直接发送其完整原文，不先填输入框再要求确认。重构现有发送入口为显式 content/source 入参，候选发送与手动输入复用相同 UUID、正文锁和异常处理。候选发送保留正在编辑的自由输入草稿；手动发送仍按现有规则清空已提交文本，启动失败时恢复。候选发送前再次验证关联最新回复，同步进入发送状态，防双击和键盘重复触发。

正文生成期间仍遵守现有生成锁；**只等待候选时**，输入和手动发送可用。发送下一轮、重新生成、切会话、编辑分支或删除后，旧候选退出当前界面，旧请求取消，迟到结果不能插入新会话。失败不会清空草稿。保留 Enter 发送、Shift+Enter 换行和中文 IME 保护。

## 独立请求、存储与并发

计划新增 `POST /api/sessions/:id/suggestions { messageId, retryOfRequestId? }` 和只读状态接口 `GET /api/sessions/:id/suggestions?messageId=...`。正文先完成落库并释放锁，前端收到完成状态后调用候选接口；正文 SSE 在原有 done 事件正常结束，不追加第二段候选等待。候选使用当前白名单模型，但强制关闭思考，独立低输出预算（初始 384 tokens）、完整请求 8 秒截止并取消上游，无自动重试。每轮通常增加一次短模型请求，耗时与成本需单独记录和验收。

候选提示使用受预算限制的角色/persona/当前激活世界书、最近完整轮次和最新完整回复；复用 Prompt 预算机制，不只给最新一句话，也不复制无限历史。候选任务指令与 RP 正文指令分开；角色内容作为上下文资料，结果作为候选数据验证。输入不能容纳必要上下文时返回候选失败，不影响正文。优先使用真实路由支持的 JSON schema；没有结构化输出能力则严格解析并校验 JSON，禁止从任意文本猜出三个选项。

为 `messages` 增加一个 nullable 候选 JSON 元数据列，保存 `state/requestId/leaseUntil/items`。候选关联现有 message ID；重新生成和续写本来就会产生新 ID，无需新建业务表。旧记录保持 NULL，历史内容和 ID 不变。候选不作为 messages 中的额外 user/assistant 消息，不进正文或后续 Prompt；JSONL 可带独立元数据，不伪装成对话。编辑分支复制正文与状态，不复制旧候选任务或结果。

候选接口先确认 owner、session、最新可见回复、`completed + stop` 和正文锁空闲，再用条件更新原子抢占独立候选 lease。重复 POST、多标签页及刷新读取同一 pending/ready/failed 状态，不再次调用模型；用户显式重试携带当前失败任务的 `retryOfRequestId`，只有对应 failed/expired 状态才能原子抢占，同一重试令牌重复提交只调用一次模型。ready 已返回则读已存结果。候选 lease 不使用、不延长正文 `generation_id`，不能阻挡下一轮。

结果落库前再次核对会话未删除、回复仍为最新版本、没有新用户轮次、没有正文生成锁，以及本任务 requestId。以上检查与写入在同一次条件更新中完成，避免检查后新一轮正文抢先发生；条件不满足即丢弃。失败时只更新本次任务，不能覆盖新任务。用户下一轮或跨标签页启动正文时使旧任务失效；上游尽可能取消，无法及时取消的结果仍必须丢弃。前端接口返回也核对会话/消息 ID。刷新只恢复已存状态，不向全部历史补请求；读取 pending 不启动推理，前端仅对当前消息通过只读接口有限轮询，最长到 lease 截止。ready 显示结果、failed/expired 显示重试，离开会话立即停止轮询；过期 lease 标为可显式重试。

输出接受 1–3 条非空字符串，去首尾空格并去重；超三条取前三条合格文本，不合格项目剔除，全部无效则失败。限制响应大小，不执行 HTML 或链接动作。所有请求继续使用 Tavern Auth0/owner 边界、Gateway skipCache 与 collectLog:false；日志只记状态、耗时和计数，不记录私人正文、思考或凭据。

## 实施顺序与验收

| 顺序 | 工作 | 必过条件 |
| --- | --- | --- |
| 1 | 真实 RP 能力核实、统一默认值/校验/请求映射、模型白名单 | 明确每个参数是否生效；所有路由分支默认关闭思考；缺省旧会话仍可读写 |
| 2 | 全局和会话参数组件、设置页分组 | 首屏思考关闭、模型可选 RP、恢复默认、范围错误、保存持久化和当前会话设置可用 |
| 3 | 候选 D1 兼容迁移、独立接口和幂等 | 隔离 D1 先验证；重复 POST/两标签页不重复付费；8 秒超时取消；不占正文锁、不污染历史 |
| 4 | 候选按钮、显式发送入口、状态隔离 | 最多三条、原文点击发送、草稿保留、候选等待时可发送；切会话/分支/重生成丢弃旧结果 |
| 5 | 视觉、PR CI、兼容发布和真实模型验收 | 固定 Linux 截图审阅导入、必需状态全绿、D1 迁移先行、Workers Builds 自动发布与线上版本核验 |

自动化覆盖缺省/非法参数、旧 JSON、白名单拒绝、默认 false 的实际请求映射、正文停止/失败/长度状态、候选非法 JSON/空值/重复/超三条、8 秒取消、并发/过期/重试、草稿和键盘发送、刷新恢复与旧结果丢弃。刷新/重复读取不暗中重试推理。

浏览器与视觉清单覆盖设置和会话设置正常/加载/错误/保存/恢复默认、候选等待/成功/失败/空结果/发送、长句、iPhone WebKit、desktop、深色、键盘与减弱动效。输入可用、无横向溢出、软键盘/安全区不遮挡操作分别检查；设备模拟不算真机。

真实 JWT/API 验收单列：RP 默认请求确实关闭思考，开启后也确实可切换；受支持参数实际生效；回复正常完成后候选可生成、点击原文进入下一轮、会话恢复一致。比较相同有限任务关闭/开启时首个正文字符耗时及可用 usage，但不把一次快响应、缺少 reasoning_content 或模型口头承诺当作关闭证明。候选延迟和额外调用成本单列；8 秒未完成的状态按真实失败记录，不能降低门槛伪装通过。

以上全部是待实施目标。本轮仅更新文档；没有运行功能测试、迁移数据库或改变线上模型请求。

## 官方契约依据与待核实项

- [Cloudflare 动态路由调用](https://developers.cloudflare.com/ai-gateway/features/dynamic-routing/usage/)：使用固定逻辑路由，实际模型由网关决定；应用选择项不能等价于任意上游模型输入。
- [Cloudflare 路由配置](https://developers.cloudflare.com/ai-gateway/features/dynamic-routing/json-configuration/)：路由可以有多分支、超时和重试，因此能力验证覆盖全部可达模型，不只验证一次返回模型。
- [OpenRouter 参数](https://openrouter.ai/docs/api_reference/parameters)、[思考参数](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)：作为供应商参数差异参考，隐藏 reasoning 和关闭 reasoning 需区分。**尚未确认 RP 的实际供应商，不据此直接采用其参数格式。**

实施时读取真实 RP 路由配置和供应商官方契约并验证透传、参数范围、关闭/开启思考、结构化输出及候选延迟；这些证据尚缺，不影响本轮完成方案，但不能宣称功能已上线。
