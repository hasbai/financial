# 实施规划

版本：2026-09-13。本文是目标方案，实际完成状态见 [PROGRESS](PROGRESS.md)。

## 1. 目标与范围

服务个人日常财务核对：快速知道有多少资产和负债、本期现金如何变化、收入支出如何形成损益；在手机上持续补全已有交易，并能手工增加漏记交易。

首期覆盖完整闭环：Auth0 登录、总览三表、流水列表与筛选、待处理队列、手工新增、科目匹配、多分录拆分、退款关联、数据质量反馈。保留复式记账能力，常用收支使用易懂表单，复杂交易切换高级分录。

后续扩展：自动账单导入、凭证附件、投资行情估值、多币种汇兑、预算、家庭共享、自动匹配规则、离线同步。首期保留扩展接口，不以这些功能阻塞上线。

## 2. 默认设计决策

| 事项 | 本方案选择 | 原因 |
| --- | --- | --- |
| 渲染 | React 客户端 SPA | 私人系统不依赖 SEO 或 SSR |
| 数据调用 | 浏览器 → Neon Data API | 已有接口，减少运维层次 |
| 业务逻辑 | PostgreSQL 视图与原子函数 | 报表口径与借贷平衡有同一事实来源 |
| 部署 | Worker `financial` 托管静态资源 | 与指定 Cloudflare 平台和域名一致 |
| 视觉 | Material UI，定制主题，移动端卡片 | 开源组件成熟，适合表单与交互 |
| 访问范围 | 单人私有账本，显式成员授权 | 同一 Auth0 tenant 的其他用户不能看账本 |
| 时间 | Asia/Shanghai，默认自然月 | 日期筛选按本地自然日解释 |
| 币种 | 首期暂按 CNY 设计 | 现有表无币种字段，迁移前确认历史数据 |
| 数据保存 | 允许草稿；只有合格已入账交易进报表 | 支持分步补录，避免缺项误入报表 |
| 金额隐私 | 一键隐藏，偏好本地保存 | 在公共场景使用手机时减少意外展示 |

“默认”可在开发前调整；历史金额符号、退款表达和期初范围必须以实际证据完成校准，不能用默认值批量改写。

## 3. 阶段与验收门槛

| 阶段 | 工作与交付物 | 依赖 | 完成标准 |
| --- | --- | --- | --- |
| P0 规划 | 现场核查、架构、业务/UI 设计、文档与 Git 仓库 | 无 | 文档自洽，已知与未知有证据标记 |
| P1 接入验证 | 核实北极小站配置；隔离 Neon 分支；JWT、RLS、视图与 RPC 小型验证；确认首期业务口径 | P0、Auth0 登录恢复 | 本人合法 token 可访问；匿名、他人、错 audience、过期、跨账本请求均失败；多表写入故障完整回滚；决定直连或 Worker 后端 |
| P2 数据契约 | 增量迁移、授权、报表视图、读写 RPC、幂等与审计、旧数据映射草案 | P1 | 分支上的真实历史数据保留；旧 ID/FK 不变；借贷平衡、退款、现金内部转账和权限测试通过 |
| P3 应用基础 | React/Vite/pnpm、MUI 主题、路由、Auth0、查询层、CI | P1；与 P2 可分工作流推进 | 登录回跳、退出清缓存、手机导航、深链接；类型检查和构建通过 |
| P4 流水闭环 | 卡片、待处理队列、筛选、补录、新增、账户选择、拆分、退款关联、冲突提示 | P2、P3 | 手机上完成一笔新增与一笔补录；重试不重复；返回保留位置；失败不丢表单；写入后相关查询刷新 |
| P5 总览报表 | 资产负债、现金流、损益、趋势、质量提示、下钻 | P2、P3 | 三表与同口径 SQL 对账；数据不完整时明确标记；跨月边界正确；指标下钻包含/排除规则一致 |
| P6 上线验收 | 真机/浏览器、生产迁移、Worker 域名、发布和回滚记录 | P4、P5、生产发布授权 | 完成验收矩阵；生产登录读写可用；既有 Auth0/Neon 消费者无回归；记录部署版本 |

建议开发顺序：先打通 P1，再让流水补录与数据质量改进先于总览最终验收。投入估计为单人约 12–18 个有效开发日，属于规划估算；不包含授权等待、历史退款/期初人工核对和额外导入功能。

## 4. 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 工资、现金消费、信用卡消费、还款、现金账户间转账 | 三表影响符合 [业务口径](DOMAIN.md) 示例 |
| 草稿缺金额/科目、成功交易无分录、未知退款 | 可在待处理队列恢复；不得当成零元完整交易 |
| 完整交易补录备注、修改账户、拆分金额 | 保存后原子提交，审计记录可追踪，报表更新 |
| 连续点击保存、网络响应丢失后重试 | 同一幂等键只产生一次结果 |
| 两设备同时编辑 | 后提交收到版本冲突，不能静默覆盖 |
| 部分退款、多次退款、撤销已入账交易 | 关联原交易，退款累计与分录一致；使用冲销留痕 |
| 不同用户/账本的交易或科目 ID | 数据库拒绝读取与写入，RPC 不绕过授权 |
| 360/390/430px 手机，768px 平板，1440px 桌面 | 无全页横向溢出，卡片与表单可用，底部操作不遮挡内容 |
| iOS Safari / Android Chrome，软键盘、旋转、返回手势 | 保存按钮可到达，滚动/焦点恢复，未保存修改有提示 |
| 200% 缩放、键盘导航、读屏、减少动效 | 关键操作可完成，状态不只靠颜色，表单错误可定位 |
| Token 过期、403、冷启动、离线、API 失败 | 不闪现他人/旧会话数据，不无限重试；保留可恢复输入 |
| 月末/跨年、期初余额缺失、重复导入 | 期间正确；显示完整性限制；不得以重复数据增厚报表 |
| `/transactions/:id` 刷新，Auth0 callback，404 | SPA 正确回退；登录后回到站内合法路径 |

## 5. 接入前仍需落实

1. 恢复 Auth0 CLI 会话后核实“北极小站”：client ID、SPA 类型、PKCE、回调、登出、web origins、API audience；若是传统 Web 应用，不直接改类型影响原站。
2. 核查当前 Neon Data API 的 JWKS/provider 和既有 `public`、`financial` 消费者。当前配置查询不含 provider 明细，不能假定已接 Auth0。
3. 在登录身份确定后把历史账本绑定到准确的 Auth0 `sub`；不能允许任意首个登录者认领。
4. 明确现金及现金等价物科目、期初覆盖日期、历史币种、退款分录含义。未确认时先做待核对状态和可用范围展示。
5. 核实 Cloudflare 域名现有 DNS 与路由。本次访问目标域名得到 Caddy 502，尚不能判断 Worker 或 DNS 配置。

这些事项不影响 P0 文档完成，但会影响后续接入、迁移或正式报表验收。
